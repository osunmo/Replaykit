# ReplayKit R1 vertical slice

The user supplied AGENTS.md as the product specification and explicitly requested implementation. This document narrows the first delivery to foundation and the R1 replay path. The entire 20-case benchmark remains a later milestone.

## Outcome

A developer can capture an actual repeated-payment incident from a PostgreSQL-backed checkout service, generate a reviewable regression test using only visible evidence, and run that test through an independent offline judge. Valid fixes preserve one charge per idempotency key; a decoy hides the error while still charging twice.

## Architecture

TypeScript ESM pnpm workspace: contracts, telemetry, replay-engine, planner, judge, CLI, and checkout-api. Zod validates boundaries. A cooperative scheduler owns named checkpoints and finite schedules, emits logical sequence events, and fails with diagnostics on timeout or cancellation.

R1 has immutable source variant artifacts: buggy creates a fresh provider key on retry; reference reuses the request idempotency key; alternate returns an existing successful payment; decoy hides duplicate-charge symptoms but retains the second charge. A synthetic payment provider is backed by PostgreSQL, so payments are durable real application state, with no real payment integration.

The candidate test lives in a separate restricted container and calls the app through its HTTP interface. App and PostgreSQL containers are connected by a Docker internal network with no external egress. Candidate containers receive no Docker socket, host checkout, judge truth, fix files, or DB credentials. A trusted supervisor gathers application telemetry and queries database state independently of candidate stdout. Candidate code is never imported on the developer host.

The rule planner is a pure function of normalized visible evidence. It recognizes a repeated idempotency-key pattern; no incident-ID lookup chooses answers. Missing required evidence produces an explicit abstention. Generated tests use node:test and assert the one-charge invariant through the public app response. Static policy checks supplement, but do not replace, isolation and the execution matrix.

## Acceptance

- Unit tests cover redaction, tier filtering, schemas, schedule ordering/deadlocks, evidence-driven planning, and strict judge rejection paths.
- PostgreSQL integration tests establish actual buggy/reference/alternate/decoy behavior.
- Smoke runs 10 fresh buggy executions and both valid fixes plus decoy, recording source/input/test hashes and real evidence.
- A same-exception/different-frame incident is rejected.
- Missing Docker is an infrastructure ERROR, never a verified result or successful abstention.
- README commands, CI, progress, decisions, threat model, limitations, and evaluation notes accurately describe tested scope.
